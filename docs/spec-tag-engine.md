# Tag engine specification (core module)

This document is the contract for the four pure-JVM tag formats in `core/`.
It is read by the implementation agents and by the Lead during review.

## Goal

`com.musictag.core.tag` must read and rewrite embedded metadata for the formats
users pick in the app. No Android dependencies, no third-party libraries,
deterministic unit tests. The module compiles with Kotlin 2.2.20 / JVM 17.

## Public API (owned by the Lead, do not modify)

`core/src/main/kotlin/com/musictag/core/tag/TagDocument.kt`:

```kotlin
class Artwork(bytes: ByteArray, mimeType: String, description: String = "") {
    companion object { fun fromBytes(bytes: ByteArray, description: String = ""): Artwork; fun sniffMimeType(bytes: ByteArray): String }
}
data class TagDocument(
    val title: String? = null, val artist: String? = null, val album: String? = null,
    val albumArtist: String? = null, val year: String? = null,
    val trackNumber: String? = null, val discNumber: String? = null,
    val genre: String? = null, val comment: String? = null,
    val lyrics: String? = null, val artwork: Artwork? = null,
)
interface TagFormat {
    val displayName: String
    val extensions: Set<String>
    fun supports(file: File): Boolean
    fun read(file: File): TagDocument
    fun write(file: File, document: TagDocument)
}
```

`TagEditor` registers `Mp3Format`, `FlacFormat`, `OggFormat`, `Mp4Format` (Kotlin
`object`s). They must implement `TagFormat` with those exact names/packages.

Semantics:

- `read` on a valid file without metadata returns an empty `TagDocument` (all null).
- `write` makes the file's modeled metadata exactly match the document:
  `null` removes that field, `null` artwork removes all cover art.
- Fields that are **not** modeled by `TagDocument` (other ID3 frames, other
  Vorbis comments, other MP4 atoms, seek tables, etc.) must be preserved.
- Audio payload and technical headers must stay byte-identical wherever the
  container allows it. Do not re-encode audio.
- Invalid/corrupt/unsupported input throws `TagException` with a Chinese
  user-facing message. Never throws raw `IOException` to callers.
- Writes must be crash-safe: write to a temp file in the same directory, fsync,
  then atomically replace the original (`Files.move(..., ATOMIC_MOVE)` with a
  `REPLACE_EXISTING` fallback). The original must be intact if anything fails.
- Strings are UTF-8 Java strings. Empty/blank text fields are treated as absent.
- Artwork: exactly one front cover is stored when `document.artwork != null`.

## Per-format requirements

### MP3 — `com.musictag.core.tag.mp3.Mp3Format` (owner: mp3-id3)

Extensions: `mp3`, `mpga` (also raw `.aac` ADTS, see below).
Magic: `ID3` tag or MPEG frame sync `0xFF Ex`.

Read:
- ID3v2.2/v2.3/v2.4 at file start. Header: `ID3`, major, revision, flags,
  syncsafe 28-bit size (all versions). Handle unsynchronisation (re-sync bytes),
  v2.3/v2.4 extended header, v2.4 footer flag.
- Frames: TIT2/TPE1/TALB/TPE2/TYER/TDRC/TRCK/TPOS/TCON/COMM/USLT/APIC.
  - title←TIT2, artist←TPE1, album←TALB, albumArtist←TPE2, year←TDRC (v2.4) or
    TYER (v2.3), trackNumber←TRCK, discNumber←TPOS, genre←TCON, comment←COMM,
    lyrics←USLT, artwork←APIC with picture type 3 (front cover), else first APIC.
  - Text encodings 0 ISO-8859-1, 1 UTF-16 (with BOM), 2 UTF-16BE, 3 UTF-8.
    Strip trailing NULs. TCON may contain `(13)` style strings — keep as-is.
- No ID3 tag → empty document (empty ID3v2 tag with zero frames is also empty).
- Trailing ID3v1 (`TAG` + 128 bytes) may be used as a fallback only when there is
  no ID3v2 tag; discard it on write (avoid stale duplicates).

Write:
- Preserve the input major version (v2.2 input may be upgraded to v2.3; default
  v2.3 when the file has no tag).
- Text encoding: v2.3 → ISO-8859-1 when representable, otherwise UTF-16LE+BOM
  (encoding 1). v2.4 → UTF-8 (encoding 3). This matters because v2.3 players
  may not accept UTF-8.
- APIC: encoding 0 description "" (empty NUL), MIME `image/jpeg`/`image/png`/
  `image/webp`, picture type 3, empty description, raw image bytes. One APIC only.
- USLT: encoding as above, language `und`, empty content descriptor, lyrics text.
- COMM: language `und`, empty description.
- Preserve unmodeled frames byte-for-byte (raw frame blocks incl. flags), drop
  only frames replaced/removed by the document.
- Rebuild tag before audio bytes; keep audio (and everything after old tag)
  byte-identical. Add ~1 KiB zero padding after frames (harmless, helps other
  editors). Keep a v2.4 footer only if the input had one? (optional).
- Raw ADTS `.aac`: metadata is an ID3v2 tag prepended to the ADTS stream; writing
  when absent prepends a new tag, audio bytes unchanged.
- `supports`: by extension (`mp3`, `mpga`, `aac`) **or** magic for files without
  a useful extension; must not claim FLAC/OGG/M4A files.

Tests (mp3): read all MP3 fixtures; write Chinese title/artist/album/lyrics +
JPEG cover into `bare.mp3` and `tagged_v24.mp3`; re-read equality (including
artwork bytes); ffprobe asserts values + `attached_pic`; ffmpeg decode OK;
null document removes everything; v2.4 stays v2.4; raw `.aac` round trip;
`tagged_v23_cover.mp3` cover bytes equal `cover.jpg`; unmodeled TXXX frame
preserved (create with ffmpeg `-metadata custom_key=...`, if needed).

### FLAC — `com.musictag.core.tag.flac.FlacFormat` (owner: flac-tags)

Extensions: `flac`. Magic: `fLaC`.

Read: parse metadata blocks (type/length) after `fLaC`. STREAMINFO(0),
PADDING(1), APPLICATION(2), SEEKTABLE(3), VORBIS_COMMENT(4), CUESHEET(5),
PICTURE(6). Vorbis comment: little-endian lengths, UTF-8 `KEY=value`.
Map TITLE, ARTIST, ALBUM, ALBUMARTIST, DATE/YEAR, TRACKNUMBER, DISCNUMBER,
GENRE, COMMENT/DESCRIPTION, LYRICS/UNSYNCEDLYRICS. Cover: first PICTURE with
type 3 (front cover), else first PICTURE. Missing comment block → empty document.

Write: keep block order, replace/insert VORBIS_COMMENT and PICTURE blocks, keep
STREAMINFO first and byte-identical, keep APPLICATION/SEEKTABLE/CUESHEET and
unknown block types, drop stray PICTURE blocks when writing a new cover, remove
all PICTURE blocks when artwork is null. Preserve unrecognized comment keys;
remove only keys that map to modeled fields before appending new ones. Update
the last-block flag correctly and write a 4 KiB PADDING block. Audio frames are
copied byte-identically after the metadata blocks.

Tests: read both fixtures (cover present in `tagged.flac`); write Chinese values
+ PNG cover to `bare.flac`; verify by read-back, ffprobe (`format_tags`,
attached pic stream), ffmpeg decode and duration; assert seektable bytes are
unchanged; remove artwork/fields and verify; unknown comment key preserved.

### OGG — `com.musictag.core.tag.ogg.OggFormat` (owner: ogg-tags)

Extensions: `ogg`, `oga`, `opus`. Magic: `OggS`.

Support Ogg Vorbis and Ogg Opus. Vorbis packets: ident (bit 0 → 1), comment
(packet type 3), setup (packet type 5). Opus: `OpusHead` ident, `OpusTags`
comment, then audio. Comments: vendor string + count + UTF-8 `KEY=value`.
Cover art in both is `METADATA_BLOCK_PICTURE` = base64 of the FLAC PICTURE block
structure (type 3 front cover), MIME/data/flags/description.

Write strategy: rewrite the header pages (identification unchanged, new comment
packet, unchanged setup packet for Vorbis) with CRC32 (poly 0x04C11DB7,
non-reflected, init 0, xor 0) and correct lacing/segment tables; then append the
original audio tail. Audio packets must stay byte-identical. If the number of
header pages changes (e.g. comment packet > 64 KiB), renumber the page sequence
numbers of the following pages and recompute their CRCs, preserving granule
positions and BOS/EOS flags, page serial and stream structure. Keep packets on
one page when they fit; split across pages with continuation flags when needed.
Reject (TagException, Chinese message) only genuinely unsupported streams
(e.g. chained/multiplexed streams, or header packets entangled with audio in one
page) — report exact reason.

Tests: read both fixtures; write Chinese + cover into `bare.ogg`/`tagged.ogg` and
`bare.opus`; read-back equality; ffprobe `format_tags`; ffmpeg decode + duration
unchanged; long lyrics (~80–120 KiB) forcing multi-page comment then read back,
decode; cover removal; ensure file still starts with `OggS` and has correct CRCs
(verify by re-parsing with your own reader; optionally `ffmpeg`).

### MP4/M4A — `com.musictag.core.tag.mp4.Mp4Format` (owner: mp4-tags)

Extensions: `m4a`, `m4b`, `mp4`. Magic: `ftyp` at offset 4.

Read: walk top-level boxes (`ftyp`, `moov`, `mdat`, `free`, `moof`…), inside
`moov` find `udta/meta/ilst` (`meta` is a full box: 4-byte version/flags before
children), read items: `©nam` title, `©ART` artist, `©alb` album, `aART`
albumArtist, `©day` year, `trkn` track, `disk` disc, `©gen` genre, `©lyr` or
`©cmt` lyrics, `covr` artwork. `data` boxes: type flags (1 = UTF-8 text,
13 = JPEG, 14 = PNG; 0 for trkn/disk) + 4-byte locale + payload. `covr` may
contain several images — take the first. Missing ilst → empty document.

Write: replace modeled items, preserve unknown ilst items, preserve all other
box contents. If `udta/meta/ilst` is missing, create `moov/udta/meta(hdlr
mdirappl + ilst)` inside `moov`. Update ancestor sizes (`ilst`, `meta`, `udta`,
`moov`). Preserve `ftyp`/`mdat` bytes and order. Handle size==1 (64-bit) and
size==0 (to EOF). Because moov size may change, adjust every `stco`/`co64` entry
and any `iloc`-style absolute offsets in the media data by the moov delta when
the media data follows moov; when moov follows mdat no offset change is needed.
(If an adjacent `free` box can absorb the delta, that is acceptable too.)
Write ISO-8859-1/UTF-8 text data boxes with locale 0, `covr` with type 13/14,
`trkn`/`disk` binary (2-byte pad, number, total, 2-byte pad).

Tests: read `tagged.m4a`; write Chinese + PNG cover into `bare.m4a` and
`faststart.m4a` and `tagged.m4a`; read-back equality; ffprobe format tags +
attached_pic; `ffmpeg -i out.m4a -f null -` OK (this proves stco offsets are
correct); duration unchanged; write twice (idempotent); remove all fields/cover;
verify unknown atom preservation if practical; verify faststart moov-before-mdat
case still plays.

## Rules for all format agents

1. Only create/modify files inside your own package and your own test file.
   Shared files listed above are Lead-owned. Other format packages are off
   limits. If you believe a shared change is needed, message the Lead instead.
2. No new Gradle dependencies, no Android imports, no reflection on JDK internals.
3. `object XxxFormat : TagFormat` must stay an object (reflection-free use).
4. Aim for clean, defensive parsing: validate sizes, cap allocations, never
   loop forever on corrupt input, close all streams (`use {}`).
5. Tests must be deterministic and fast (< 10 s per format) and use JUnit 4.
6. Before reporting done: `tools/build.ps1 -Tasks ":core:test","--tests","<your package>.*"`
   must be green, and paste the final test summary in your report.
